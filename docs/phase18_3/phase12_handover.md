# Phase 18.4 preparation — local recommendation generation compatibility

This is a source review only; no Recommendation Generation implementation or route was changed. Phase 18 and T17 remain open. The frozen Q1S query-understanding candidate is experimental and is not approved for production. Phase 18.4 may test compatibility offline with existing grounded fixtures and a single native Ollama generation request, preserving the model and public recommendation contract until evidence supports a separately reviewed change.

Python already owns product selection, ranking, price/rating values, evidence-ID generation and final assembly. Candidate IDs/order, numeric comparisons, compact fact selection, citation validation, and deterministic missing-information templates could be supplied by Python to simplify a future local generation task. The LLM could focus on concise grounded wording. These are hypotheses for measured compatibility experiments, not implemented changes or a mandate to redesign schemas.

Evidence-ID existence is not proof that a free-text claim is entailed. In the inspected validator, surviving evidence references are checked, but arbitrary `summary_reason` and `comparison_note` text is retained; strong sounding prose can exceed the cited facts. Fallback text includes phrases such as “Authentic” in some paths, which deserves evidence review rather than automatic trust. Missing evidence must not become a claim of absent capability. A local model that emits valid JSON can still hallucinate specifications or durability, as earlier T17 evidence warns.

Recommended bounded Phase 18.4 work: freeze representative ordered product/evidence inputs, audit prompt length and schema complexity, run the unchanged native model against existing contracts, record raw/validated/grounded/fallback stages separately, measure unsupported claims and candidate/citation preservation, and compare a minimal wording-only candidate if baseline fails. Keep a zero-external-provider guard, no downloads, no paid calls and no route activation. Obtain human review of groundedness and language quality. Do not spend/reset the exhausted historical T17 ledger.

Query-understanding prerequisites remain visible: preference F1 and coverage miss targets, independent labels are absent, some named brands still require clarification, and V1 cannot represent true exclusions. Downstream inspection used real local TF-IDF and CrossEncoder resources but not a live dense/database pipeline. Several newly unblocked queries retrieved a cable/headset/steering cover instead of the requested pad/speaker/body cover. Phase 12 explanations must not paper over wrong product types or claim mandatory attributes are satisfied merely because broad category and price filters passed. Upstream clarification/failure must remain terminal.
