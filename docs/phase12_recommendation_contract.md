# Phase 12 — Recommendation Generation Typed Contract

**Contract Version:** `1.0.0`  
**Status:** **ACTIVE / FROZEN FOR PROTOTYPE**  
**Module:** `shopassist.recommendation`

---

## 1. Overview & Handoff Scope

Phase 12 consumes typed upstream results from Phase 8, Phase 9, and Phase 11, and emits a self-contained, typed `RecommendationResult` suitable for direct consumption by the FastAPI application (Phase 15) and Telegram Bot (Phase 16).

Consumers do not need to understand LLM provider details (OpenRouter / Groq), raw prompts, JSON Schema formatting, or evidence extraction rules.

---

## 2. Input Contracts & Preconditions

### 2.1 Interface Signature

```python
async def generate(
    self,
    query_result: QueryUnderstandingResult,
    preference_result: PreferenceRepresentationResult | None,
    reranking_result: RerankingResult,
) -> RecommendationResult: ...
```

A synchronous blocking convenience wrapper is also provided for non-async callers:

```python
def generate_sync(
    self,
    query_result: QueryUnderstandingResult,
    preference_result: PreferenceRepresentationResult | None,
    reranking_result: RerankingResult,
) -> RecommendationResult: ...
```

### 2.2 Upstream Status Invariants

Phase 12 fails closed or passes through upstream stop states without invoking LLM generation:

| Upstream Status | Phase 12 Result Status | Behavior |
|---|---|---|
| `query_result.status == "CLARIFICATION_REQUIRED"` | `RecommendationStatus.CLARIFICATION_REQUIRED` | Halts immediately; passes through query understanding diagnostics. |
| `query_result.status == "UNSUPPORTED_INTENT"` | `RecommendationStatus.UNSUPPORTED_INTENT` | Halts immediately; avoids unnecessary LLM generation calls. |
| `query_result.status == "INVALID_INPUT"` | `RecommendationStatus.INVALID_INPUT` | Halts immediately. |
| `preference_result.status in (CLARIFICATION, INVALID, ...)` | Matching `RecommendationStatus` | Halts immediately. |
| `reranking_result.status != RerankingStatus.SUCCESS` | Matching `RecommendationStatus` | Maps to `RETRIEVAL_FAILURE` or `NO_RESULTS`. |
| `len(reranking_result.products) == 0` | `RecommendationStatus.NO_RESULTS` | Returns graceful empty result with friendly overview message. |

## 3. Output Schema Specification

### 3.1 `RecommendationStatus`

```python
class RecommendationStatus(str, Enum):
    SUCCESS = "SUCCESS"
    NO_RESULTS = "NO_RESULTS"
    INVALID_INPUT = "INVALID_INPUT"
    CLARIFICATION_REQUIRED = "CLARIFICATION_REQUIRED"
    UNSUPPORTED_INTENT = "UNSUPPORTED_INTENT"
    RETRIEVAL_FAILURE = "RETRIEVAL_FAILURE"
    GENERATION_FAILURE = "GENERATION_FAILURE"
    VALIDATION_FAILURE = "VALIDATION_FAILURE"
    DOWNSTREAM_DEGRADED = "DOWNSTREAM_DEGRADED"
```

### 3.2 `RecommendationResult`

The top-level model returned by the service:

```python
class RecommendationResult(BaseModel):
    contract_version: str = "1.0.0"
    status: RecommendationStatus
    overview: str
    products: list[RecommendedProduct] = Field(default_factory=list)
    total_candidates_received: int = 0
    recommended_count: int = 0
    applied_constraints: dict[str, Any] = Field(default_factory=dict)
    language: str = "auto"
    model_name: str | None = None
    usage: TokenUsage = Field(default_factory=TokenUsage)
    warnings: list[str] = Field(default_factory=list)
    diagnostic_reason: str | None = None
```

### 3.3 `RecommendedProduct`

Each product combines authoritative catalog fields preserved from Phase 11 with grounded explanations:

```python
class RecommendedProduct(BaseModel):
    # Authoritative fields preserved from Phase 11
    product_id: str
    product_name: str
    brand: str | None = None
    category: str
    discounted_price: float
    rating: float | None = None
    currency: str = "INR"
    original_rank: int
    reranked_rank: int
    rrf_score: float

    # Grounded explanation fields generated by LLM
    summary_reason: str
    strengths: list[ProductClaim] = Field(default_factory=list)
    limitations: list[ProductClaim] = Field(default_factory=list)
    comparison_note: str | None = None

    # Traceable evidence catalog extracted from Phase 11 metadata
    available_evidence: list[ProductEvidence] = Field(default_factory=list)
```

### 3.4 `ProductClaim` & `ProductEvidence`

```python
class ProductClaim(BaseModel):
    claim: str
    evidence_ids: list[str] = Field(default_factory=list)

class ProductEvidence(BaseModel):
    evidence_id: str          # Format: {product_id}-E{counter}
    product_id: str           # Must match parent product
    source_field: str         # "product_name", "discounted_price", "specifications", etc.
    text: str                 # Exact verifiable catalog fact
```

### 3.5 `TokenUsage`

```python
class TokenUsage(BaseModel):
    prompt_tokens: int = 0
    completion_tokens: int = 0
    total_tokens: int = 0
    reasoning_tokens: int = 0
    latency_ms: float = 0.0
    estimated_cost_usd: float = 0.0
```

## 4. Groq Strict JSON Schema Definition

For inference with `openai/gpt-oss-20b`, Groq requires JSON Schema Strict Mode (`strict: true`). All properties are explicitly required and `additionalProperties: false` is enforced:

```json
{
  "type": "json_schema",
  "json_schema": {
    "name": "recommendation_payload",
    "strict": true,
    "schema": {
      "type": "object",
      "properties": {
        "overview": { "type": "string" },
        "products": {
          "type": "array",
          "items": {
            "type": "object",
            "properties": {
              "product_id": { "type": "string" },
              "summary_reason": { "type": "string" },
              "strengths": {
                "type": "array",
                "items": {
                  "type": "object",
                  "properties": {
                    "claim": { "type": "string" },
                    "evidence_ids": { "type": "array", "items": { "type": "string" } }
                  },
                  "required": ["claim", "evidence_ids"],
                  "additionalProperties": false
                }
              },
              "limitations": {
                "type": "array",
                "items": {
                  "type": "object",
                  "properties": {
                    "claim": { "type": "string" },
                    "evidence_ids": { "type": "array", "items": { "type": "string" } }
                  },
                  "required": ["claim", "evidence_ids"],
                  "additionalProperties": false
                }
              },
              "comparison_note": { "type": ["string", "null"] }
            },
            "required": ["product_id", "summary_reason", "strengths", "limitations", "comparison_note"],
            "additionalProperties": false
          }
        }
      },
      "required": ["overview", "products"],
      "additionalProperties": false
    }
  }
}
```

## 5. Phase 15 Handoff Readiness

1. **Serialization:** `RecommendationResult.to_dict()` and `model_dump()` provide standard JSON serialization for FastAPI HTTP response models.
2. **Deterministic Metadata:** Frontend or Telegram bots can display prices, brands, and ratings directly without worrying about LLM corruption.
3. **Traceability:** Frontend UIs can render tooltips or tags on strengths highlighting the exact catalog source (e.g. clicking `[P001-E3]` shows `specifications: Upper Material: Mesh`).
4. **Localization:** Language detection seamlessly supports English and Vietnamese outputs according to user query intent.
